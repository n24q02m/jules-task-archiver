## 2025-02-24 - Map Lookup and Loop Overhead in Hot Paths
**Learning:** In performance-critical hot paths (like parsing and grouping thousands of tasks), using `for...of` loops and array iteration methods like `.some()` introduces measurable closure allocation and iteration overhead. Similarly, a double Map lookup using `map.has(key)` followed by `map.set(key, [])` or `map.get(key)` requires two hashing operations.
**Action:** Replace array methods (`.some()`, `.forEach()`) and `for...of` loops with standard `for` loops in high-frequency functions. For map insertion/grouping, use a single `map.get(key)` lookup, check for `undefined`, and then assign to reduce hashing overhead.
## 2025-02-24 - Replace ReDoS Regex with State Machine
**Learning:** Using regex with nested capture groups/replacements on large unparsed JSON strings (like batchexecute payloads) allocates large intermediate matches and suffers from backtracking or iteration overhead (ReDoS vulnerability). A fast path regex (`!/[\x00-\x1F]/.test(str)`) helps for clean data, but performance drops severely when it fails or when iterating over the matches.
**Action:** Replace complex nested regex string manipulation with a single-pass `for` loop state machine using `charCodeAt()`. This prevents backtracking, minimizes intermediate string allocations, and is significantly faster for large payloads, especially when control characters are present.
