## 2025-02-24 - Map Lookup and Loop Overhead in Hot Paths
**Learning:** In performance-critical hot paths (like parsing and grouping thousands of tasks), using `for...of` loops and array iteration methods like `.some()` introduces measurable closure allocation and iteration overhead. Similarly, a double Map lookup using `map.has(key)` followed by `map.set(key, [])` or `map.get(key)` requires two hashing operations.
**Action:** Replace array methods (`.some()`, `.forEach()`) and `for...of` loops with standard `for` loops in high-frequency functions. For map insertion/grouping, use a single `map.get(key)` lookup, check for `undefined`, and then assign to reduce hashing overhead.## 2025-02-24 - Negligible Micro-Optimizations
**Learning:** PRs containing micro-optimizations (e.g. replacing a double map lookup with a single map lookup) that offer negligible or unmeasured benefits in non-hot paths will be rejected as churn, especially if they carry any readability cost.
**Action:** Do not submit micro-optimizations unless they have a clear, measurable benchmark proving a significant win, or unless they are located in a confirmed, high-frequency hot path where the optimization is demonstrably necessary.
